## 课程与学习方法 { #faq-1 }

??? question "这门课需要什么基础？数学不好能学吗？"

    会一点 Python 就可以开始，附录 A 是本书用到的 Python 速查。全书公式只保留最必要的部分，并配有“算一算”的小计算，用加减乘除和简单的对数就能跟上。第 8、9 章会出现矩阵和梯度，教材都用例子解释了直观含义，不要求推导。详见 [1.7.3 节](../chapters/01-intro/index.md#173)。

??? question "全书分成哪几部分？应该按什么顺序学？"

    全书分为基础篇（第 1–3 章）、分析篇（第 4–7 章）、模型篇（第 8–9 章）和应用篇（第 10–12 章），前后环环相扣，建议按顺序学。每章开头的“先修要求”列出了需要先掌握的内容，[学习图谱](../learning-graph/index.md)可以查看每个概念的学习路径。详见 [1.7.1 节](../chapters/01-intro/index.md#171)。

??? question "★ 实验和 ☆ 实验有什么区别？都要做吗？"

    ★ 是基础实验，建议每位同学都完成；☆ 是拓展实验，供有兴趣、有条件的同学选做。课内学时有限，老师通常从每章挑一个在课内完成，其余课后自己做。详见 [1.7.2 节](../chapters/01-intro/index.md#172)。

??? question "书上标着“待实测”的实验是什么意思？"

    这些实验需要下载模型或调用大模型 API，编者的编写环境无法联网，所以没有给出运行结果，而是附了一张记录表，请你运行后自己填写。大模型每次的回答都可能不同，你的结果和同学不一样是正常的。需要联网的实验清单见 [附录 C.5](../appendix/c-environment.md#c5)。

??? question "课后练习怎么做？答案在哪里？"

    每章末尾的选择题和判断题可以直接在网页上作答，选完立即显示对错，点开“答案与解析”能看到解释和对应的正文小节。填空、简答和实践题的参考要点也放在折叠框里，建议先自己写，再展开对照。

??? question "可以用大模型帮我学习、写作业吗？"

    可以用它解释概念、检查代码错误、出练习题，但不要让它直接写完作业或实验报告，更不要隐瞒 AI 的使用。考试、测验中要遵守规定。详见 [12.6.2 节](../chapters/12-ethics/index.md#1262-ai)。

??? question "学完这门课能做什么工作？"

    相关岗位包括 AI 训练师（数据标注与质检）、提示词工程师、大模型应用开发、智能客服运维、文本方向的数据分析等，教材 1.6.4 节列出了各岗位对应的章节。详见 [1.6.4 节](../chapters/01-intro/index.md#164-nlp)。

## 实验环境与排错 { #faq-2 }

??? question "电脑配置不高，能做实验吗？需要显卡吗？"

    全书实验都可以在 CPU 上完成，内存 8GB 即可起步；运行本地大模型（实验 9-3、10-3）建议 16GB。没有合适的电脑，可以用魔搭社区的免费在线 Notebook。详见 [附录 C.1](../appendix/c-environment.md#c1)。

??? question "应该装哪个版本的 Python？"

    推荐 Python 3.11（教材编写时使用 3.11），支持 3.10–3.12。不要用刚发布的最新版本，部分库（如 jieba）可能安装失败；可以用 `conda create -n nlp python=3.11` 另建一个环境。详见 [附录 C.1](../appendix/c-environment.md#c1)。

??? question "pip 安装很慢或失败怎么办？"

    使用清华大学的 PyPI 镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`。`labs/requirements.txt` 列出了编写时实测通过的版本。详见 [附录 C.2](../appendix/c-environment.md#c2)。

??? question "Hugging Face 上的模型下载不下来怎么办？"

    先设置镜像环境变量 `HF_ENDPOINT=https://hf-mirror.com`，并在同一个命令行窗口里运行程序；也可以从魔搭社区下载，或者请老师把模型拷到 U 盘，在代码里用文件夹路径代替模型名称。详见 [附录 C.3](../appendix/c-environment.md#c3)。

??? question "读文件时中文变成乱码，怎么办？"

    乱码大多是“用错误的编码去解读文字”造成的。读写文件时明确写上 `encoding="utf-8"`；如果文件是 GBK 编码，就用 `encoding="gbk"` 打开。详见 [2.2.2 节](../chapters/02-preprocessing/index.md#222) 和 [2.2.3 节](../chapters/02-preprocessing/index.md#223)。

??? question "调用大模型 API 报 401、402、429 等错误是什么意思？"

    401 通常是 API Key 错误或复制不完整；402 是余额不足；429 是调用太频繁，可以在循环里加 `time.sleep(1)`；`KeyError` 说明环境变量没有设置或不在同一个窗口里。完整对照表见 [附录 D.7](../appendix/d-llm-api.md#d7)。

??? question "API Key 应该怎样保管？调用大模型要花多少钱？"

    API Key 不要写进代码、不要截图、不要上传，最好在控制台设置消费上限。费用按 Token 计算，像实验 6-3 对 100 条评论做分类，通常不到 1 角钱；先用 10 条数据调试，再批量运行。详见 [附录 D.5](../appendix/d-llm-api.md#d5) 和 [附录 D.6](../appendix/d-llm-api.md#d6)。

??? question "程序报错看不懂，应该怎么办？"

    先读报错信息的最后一行，再查 [附录 A.8 常见错误速查](../appendix/a-python.md#a8) 和每个实验后面的“常见问题排查”表，最后再求助同学、老师或大模型。详见 [1.7.3 节](../chapters/01-intro/index.md#173)。

## 文本处理与分词 { #faq-3 }

??? question "中文处理比英文难在哪里？"

    中文词与词之间没有空格，需要先分词；切分歧义多（如“乒乓球拍卖完了”）；网络新词层出不穷；还有简繁体、全半角等问题。详见 [1.4 节](../chapters/01-intro/index.md#14)。

??? question "用了大模型，还需要做文本预处理吗？"

    要做基础清洗（编码、网页标签、去重、隐私脱敏），但去停用词、词干提取这类步骤只适合词袋、TF-IDF 等传统方法；交给 BERT 或大模型的文本应保留完整的句子。详见 [2.5.5 节](../chapters/02-preprocessing/index.md#255)。

??? question "为什么清洗的顺序很重要？"

    例如应该先删 HTML 标签再处理标点，先统一写法再去重：两条评论可能只差一个表情或一个中英文逗号，清洗后才是重复的。可以在[文本清洗流水线](../sims/cleaning-pipeline/index.md)动画里体验错误的顺序。详见 [2.6.5 节](../chapters/02-preprocessing/index.md#265)。

??? question "正向最大匹配和逆向最大匹配有什么区别？哪个更准？"

    正向从左往右切，查不到就去掉最后一个字；逆向从右往左切，查不到就去掉最前面一个字。中文里逆向的错误率通常更低，但这只是经验规律。可以在[最大匹配分词](../sims/max-match/index.md)动画里逐步对比。详见 [3.3.1 节](../chapters/03-lexical/index.md#331)。

??? question "大模型的 Token 和 jieba 切出来的“词”是一回事吗？"

    不是。Token 是分词器（如 BPE）为模型计算服务切出来的片段，不一定符合人对“词”的理解；jieba 切出的是符合语言习惯的词，在关键词统计、建索引、词云等任务中仍是首选。详见 [3.6.3 节](../chapters/03-lexical/index.md#363-token)。

??? question "一个汉字大约是几个 Token？"

    取决于模型的分词器。教材用通义千问的分词器实测，中文平均每个 Token 约 2.1 个字符；附录 D 估算费用时按 1 个汉字约 0.6–1 个 Token 计算。详见 [3.6.3 节](../chapters/03-lexical/index.md#363-token) 和实验 3-3。

## 文本表示与检索 { #faq-4 }

??? question "TF-IDF 为什么能找出关键词？"

    TF 衡量词在这篇文章里出现得多不多，IDF 衡量它在所有文章里常不常见，两者相乘，“在这篇文章里出现多、在别处出现少”的词得分最高。可以用[TF-IDF 计算器](../sims/tfidf-calculator/index.md)动手算。详见 [5.4.1 节](../chapters/05-representation/index.md#541)。

??? question "BM25 比 TF-IDF 好在哪里？"

    BM25 让词频的作用逐渐“饱和”，防止靠堆砌关键词刷排名，并对过长的文章做长度惩罚。它不需要训练，至今仍是搜索引擎和 RAG 关键词检索的标准方法。详见 [5.4.4 节](../chapters/05-representation/index.md#544-tf-idf-bm25)。

??? question "为什么文本相似度常用余弦相似度，而不用距离？"

    余弦相似度只看两个向量的方向、不看长短，同一主题的长文章和短文章方向接近，相似度依然很高；直线距离会被文章长短影响。详见 [5.5.1 节](../chapters/05-representation/index.md#551)。

??? question "词向量和独热编码有什么不同？"

    独热编码的维度等于词表大小，任意两个词都“毫不相干”；词向量是 100–300 维的稠密向量，从大量文本中学出来，意思相近的词向量也相近。详见 [5.6.2 节](../chapters/05-representation/index.md#562)。

??? question "Word2Vec 有什么不足？后来是怎样解决的？"

    Word2Vec 给每个词只学一个向量，无法区分多义词（如“苹果”）。BERT 等模型用自注意力为同一个词在不同句子中算出不同的向量，即“上下文相关的词向量”。详见 [5.6.5 节](../chapters/05-representation/index.md#565) 和 [9.1.3 节](../chapters/09-transformer/index.md#913)。

??? question "关键词检索和语义检索各有什么优缺点？"

    关键词检索（如 BM25）对专有名词、型号、法条编号这类“必须字面一致”的查询很可靠，但不懂同义说法；语义检索能匹配意思相近的说法，但可能漏掉精确的关键词。实际系统常把两者结合成混合检索。详见 [5.7.3 节](../chapters/05-representation/index.md#573) 和 [11.4.4 节](../chapters/11-qa-rag-agent/index.md#1144)。

## 机器学习与评价 { #faq-5 }

??? question "准确率很高，模型就一定好吗？"

    不一定。当类别不平衡时，把所有样本都猜成多数类也能得到很高的准确率。评价时应先算出这条“最低参照线”，再看每个类别的精确率、召回率和 F1。详见 [6.4.3 节](../chapters/06-classification/index.md#643)。

??? question "精确率和召回率哪个更重要？"

    看业务需要：漏掉的代价大（如差评预警、疾病筛查）时更看重召回率；误报的代价大（如垃圾邮件过滤，把正常邮件当垃圾删掉）时更看重精确率。调整阈值就是在两者之间做选择，可以在[阈值与混淆矩阵](../sims/threshold-confusion/index.md)动画里拖动体验。详见 [6.4.4 节](../chapters/06-classification/index.md#644)。

??? question "什么是过拟合？怎样发现和防止？"

    过拟合是模型把训练数据“死记硬背”下来，训练集成绩很好、测试集成绩差。增加训练数据、简化模型、正则化、随机失活等都能缓解。详见 [6.2.3 节](../chapters/06-classification/index.md#623) 和 [8.2.6 节](../chapters/08-deep-learning/index.md#826)。

??? question "文本分类用传统模型还是大模型？"

    传统模型（TF-IDF + 逻辑回归）快、便宜、可本地运行，但需要数千条标注数据；大模型零样本几乎不需要标注，换任务只改提示词，但慢、按 Token 付费。常见做法是用大模型标注数据，再训练一个小模型上线。详见 [6.6.3 节](../chapters/06-classification/index.md#663)。

??? question "NER 的评价为什么要说明“严格”还是“宽松”标准？"

    严格标准要求实体的边界和类型都完全正确，宽松标准只要有重叠且类型相同就算对，同一个模型按两种标准算出的 F1 可能相差很多，不说明就没有可比性。详见 [7.2.5 节](../chapters/07-ner/index.md#725)。

??? question "BLEU 分数高，翻译就一定好吗？"

    不一定。BLEU 只数 n 元组的重合，不懂同义改写：意思完全正确但换了说法的译文 BLEU 可能很低，加一个 not 意思相反的译文 BLEU 却可能很高。它适合在大量句子上比较系统，不适合评判单个句子。可以用[BLEU 计算器](../sims/bleu-calculator/index.md)验证。详见 [10.5.3 节](../chapters/10-generation/index.md#1053-bleu)。

## 深度学习与 Transformer { #faq-6 }

??? question "为什么神经网络需要激活函数？"

    没有激活函数，每一层都只是“乘权重再相加”，多层叠加以后仍然是线性运算，和一层没有区别，解决不了“异或”这类问题。激活函数为网络引入了非线性。详见 [8.2.4 节](../chapters/08-deep-learning/index.md#824)。

??? question "RNN 为什么记不住长句子开头的内容？"

    训练时误差要一步步传回前面的时刻，每一步都乘上一个通常小于 1 的数，传得越远梯度越小，这就是梯度消失。LSTM 和 GRU 用“门”来缓解这个问题。可以在[RNN 逐步展开](../sims/rnn-unroll/index.md)动画里观察。详见 [8.4.4 节](../chapters/08-deep-learning/index.md#844-rnn)。

??? question "为什么 Transformer 取代了 RNN？"

    自注意力让任意两个词之间“直达”，不存在长距离遗忘；所有词可以并行计算，非常适合 GPU。代价是计算量随序列长度的平方增长。详见 [8.7.1 节](../chapters/08-deep-learning/index.md#871-transformer-rnn) 和 [9.1.4 节](../chapters/09-transformer/index.md#914-querykeyvalue)。

??? question "Query、Key、Value 到底是什么？"

    可以用图书馆来理解：Q 是你的问题，K 是每本书的书名和关键词，V 是书的内容。Q 和每个 K 比对得出权重，再按权重综合各本书的 V。可以在[自注意力热力图](../sims/self-attention/index.md)里一步步看计算过程。详见 [9.1.4 节](../chapters/09-transformer/index.md#914-querykeyvalue)。

??? question "BERT 和 GPT 有什么区别？"

    BERT 用 Transformer 的编码器，做“完形填空”式预训练，能同时看左右两边，擅长理解类任务；GPT 用解码器，从左到右预测下一个词，擅长生成。详见 [9.2.5 节](../chapters/09-transformer/index.md#925-transformer)、[9.3.2 节](../chapters/09-transformer/index.md#932-bert) 和 [9.3.3 节](../chapters/09-transformer/index.md#933-gpt)。

??? question "模型名称里的“7B”是什么意思？普通电脑能跑吗？"

    7B 表示 70 亿个参数。按 16 位存储约需 14GB 显存；经过 4 位量化后约需 4–5GB 内存，普通电脑也能运行，实验 10-3 会在本地运行量化模型。详见 [9.4.4 节](../chapters/09-transformer/index.md#944)。

??? question "LoRA 为什么能用很少的资源微调大模型？"

    LoRA 冻结原模型的参数，只训练两个很“瘦”的矩阵来近似参数的变化量，需要训练的参数往往不到原来的百分之几，每个任务只需保存几 MB 到几十 MB 的“插件”。详见 [9.5.2 节](../chapters/09-transformer/index.md#952-lora)。

## 大模型的使用 { #faq-7 }

??? question "大模型为什么会“一本正经地胡说八道”？"

    这叫幻觉：大模型按概率生成看似通顺的文字，并不会核实事实，还存在知识截止的问题。应对方法是核实关键信息，或者用检索增强生成让它“有据可查”。详见 [9.4.5 节](../chapters/09-transformer/index.md#945)。

??? question "温度和 Top-p 应该怎样设置？"

    翻译、抽取、分类、代码用低温度（0–0.3）；问答、摘要用 0.3–0.7；写作、头脑风暴用 0.7–1.0、Top-p 0.9 左右。一般只调其中一个。可以在[温度与 Top-p 采样](../sims/temperature-sampling/index.md)动画里体验。详见 [10.6.3 节](../chapters/10-generation/index.md#1063)。

??? question "怎样写出好的提示词？"

    讲清角色、任务、背景资料和输出格式，必要时给几个示例（少样本提示），复杂推理可以让模型“一步一步想”（思维链）。写好后用一批测试问题检验，再迭代修改。详见 [11.3.2 节](../chapters/11-qa-rag-agent/index.md#1132)。

??? question "同一个问题问两次，大模型的回答为什么不一样？"

    大模型生成时通常按概率随机采样，温度越高，结果越多样。如果需要稳定、可复现的输出，可以把温度设为 0 或很小的值。详见 [10.6.3 节](../chapters/10-generation/index.md#1063)。

??? question "使用在线大模型时，哪些信息不能输入？"

    不要输入身份证号、银行卡号、密码、病历等敏感信息，也不要上传他人的个人资料和单位的保密资料；处理工作资料前先确认单位是否允许，必要时先脱敏或使用本地部署的模型。详见 [12.3.3 节](../chapters/12-ethics/index.md#1233)。

## RAG 与智能体 { #faq-8 }

??? question "什么是 RAG？为什么需要它？"

    RAG（检索增强生成）先从知识库中检索相关资料，再让大模型根据资料回答。它能让模型回答私有资料和最新知识，给出引用来源，并减少幻觉。详见 [11.4.1 节](../chapters/11-qa-rag-agent/index.md#1141-rag)。

??? question "RAG 和微调应该怎样选？"

    想让模型“知道”新知识、私有资料，用 RAG，更新文档即可生效；想让模型“学会”新的行为、风格或固定格式，用微调。两者也可以结合。详见 [11.4.7 节](../chapters/11-qa-rag-agent/index.md#1147-rag)。

??? question "RAG 的文档应该切多大？"

    太大会混入多个主题、浪费 Token，太小会把一句话切断。结构清晰的文档按章节、条款切，结构不明显的长文本可以每 300–500 字切一块并保留重叠。可以在[RAG 切块实验](../sims/rag-chunking/index.md)里对比。详见 [11.4.3 节](../chapters/11-qa-rag-agent/index.md#1143)。

??? question "RAG 系统回答错了，应该从哪里查起？"

    先看检索到的片段里有没有正确答案：没有，就改进切块、换嵌入模型、用混合检索或改写问题；有但回答错了，就改进提示词或换更强的模型。详见 [11.4.6 节](../chapters/11-qa-rag-agent/index.md#1146-rag)。

??? question "智能体和普通聊天机器人有什么不同？"

    聊天机器人只会“说”，智能体能调用工具“做”：查资料、计算、调用接口，按“思考—行动—观察”的循环一步步完成任务。可以在[ReAct 执行回放](../sims/react-replay/index.md)里看完整过程。详见 [11.5.1 节](../chapters/11-qa-rag-agent/index.md#1151) 和 [11.5.3 节](../chapters/11-qa-rag-agent/index.md#1153-react)。

??? question "MCP 是什么？"

    MCP（模型上下文协议）是大模型应用连接外部工具和数据源的标准接口，可以类比为电脑上的 USB 接口：工具按 MCP 标准包装一次，任何支持 MCP 的智能体应用都能直接接入。详见 [11.5.4 节](../chapters/11-qa-rag-agent/index.md#1154-mcp)。

## 伦理、安全与法律 { #faq-9 }

??? question "模型的偏见是从哪里来的？"

    主要来自训练数据：数据里本来就有的社会偏见、某些群体的数据太少、标注者的主观判断，都会被模型学去。详见 [12.2.1 节](../chapters/12-ethics/index.md#1221)。

??? question "什么是提示注入？能完全防住吗？"

    提示注入是把恶意指令伪装成数据混进模型的输入，劫持模型的行为，分为直接注入和藏在网页、邮件、文档里的间接注入。目前没有任何一种方法能完全防住，只能设置多道防线，其中最重要的是权限控制：机密信息不放进提示词，危险操作要人工确认。详见 [12.4.2 节](../chapters/12-ethics/index.md#1242) 和 [12.4.3 节](../chapters/12-ethics/index.md#1243)。

??? question "去标识化和匿名化有什么区别？"

    去标识化后的数据借助额外信息（如编号对照表）仍能识别到个人，在法律上仍属于个人信息；匿名化后无法识别特定个人且不能复原，不再属于个人信息。详见 [12.3.3 节](../chapters/12-ethics/index.md#1233)。

??? question "开发 NLP 应用要遵守哪些法律法规？"

    我国主要有《网络安全法》《数据安全法》《个人信息保护法》三部法律，以及算法推荐、深度合成、生成式人工智能服务、生成合成内容标识等方面的部门规章；AI 生成的内容要按规定添加标识。12.5.4 节给出了一份项目合规检查清单。详见 [12.5.1 节](../chapters/12-ethics/index.md#1251) 和 [12.5.4 节](../chapters/12-ethics/index.md#1254)。
